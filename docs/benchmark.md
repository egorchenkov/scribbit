# Разделение говорящих: качество и скорость

Стенд — открытые записи совещаний [AMI](https://groups.inf.ed.ac.uk/ami/corpus/) (CC BY 4.0):
ES2004a (17,5 мин) и IS1009a (14 мин), по 4 участника, эталонная разметка из
[pyannote/AMI-diarization-setup](https://github.com/pyannote/AMI-diarization-setup). Для проверки
сшивки говорящих между частями обе записи склеены в одну (31,5 мин, 8 разных людей).
Метрика — DER (доля времени с ошибкой: пропуск речи + лишняя речь + перепутанный говорящий),
кадры 10 мс, коллар 0,25 с, перекрытия учитываются (`tools/bench/der.py`). Сервер — 4 ядра ARM
Neoverse-N1 (Oracle), под посторонней нагрузкой, поэтому время — ориентир, а не точный замер.
Команды — `docs/BUILD.md`.

## Движок диаризации (sherpa-onnx: pyannote-3.0 + TitaNet-small), запись целиком
| Настройка | ES2004a DER | IS1009a DER | Найдено говорящих (из 4) |
|---|---|---|---|
| порог 0.75, шаг 0.25 (v0.1.x) | 27,3 % | 23,7 % | 26 / 25 |
| порог 0.6 | 42,7 % | 33,1 % | 39 / 37 |
| **порог 0.9** | **19,5 %** | **21,1 %** | 13 / 15 |
| порог 1.05 | 17,7 % | 25,8 % | 7 / 6 |
| шаг окна 0.5 (в 1,8 раза быстрее) | 39,4 % | 23,0 % | 18 / 19 |
| WeSpeaker ResNet34 вместо TitaNet (в 3 раза медленнее) | 35,3 % | — | 19 / — |
| TitaNet, сжатый в int8 (скорость та же) | 55,7 % | 40,8 % | 2 / 1 |

Лишние «говорящие» — в основном осколки на несколько секунд (кашель, смех, перекрытия);
приложение присоединяет их к ближайшему настоящему участнику (кластер < 6 с в части).
Потоки: 1 поток ≈ 4 потока по скорости (модели маленькие), поэтому части считаются
параллельно однопоточными экземплярами, а не одна часть многими потоками.

## Весь конвейер приложения на 31,5 мин / 8 человек (`tools/jvm-check`)
| Часть | Порог сшивки | DER | Найдено (из 8) |
|---|---|---|---|
| 10 мин | 0.5 | 20,0 % | 7 |
| **5 мин (v0.2)** | **0.6** | **20,8 %** | **7** |
| 5 мин | 0.5 | 20,8 % | 7 |
| 5 мин | 0.4 | 33,3 % | 5 (сливает разных людей) |
| 3 мин | 0.5 | 22,1 % | 7 |

**Было / стало** на той же записи: v0.1.2 — 380 с, DER 31,7 %, 15 «говорящих» из 8;
v0.2.0 — 241 с, DER 20,8 %, 7 из 8.

Время на сервере: ~230–270 с на 31,5 мин аудио вместе с распознаванием; поиск говорящих
идёт параллельно с распознаванием предыдущей части (раньше — последовательно).
